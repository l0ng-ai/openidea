OpenIDEA highlights Zig files (`.zig`) and Zig package manifests (`.zon`) out of the box, and reads the standard library and fetched `build.zig.zon` packages into **External Libraries**. Code intelligence comes from ZLS. See the [support matrix](/en/languages/index) for other languages.

## Language server

ZLS ([zigtools/zls](https://github.com/zigtools/zls)) provides completion, hover, navigation, references, rename, formatting, semantic tokens, inlay hints, diagnostics and code actions for Zig and `.zon` files. It is installed from its GitHub releases with **Install** in **Settings › Languages & Frameworks › Language Servers**, or put `zls` on `PATH`; the same page sets the executable.

ZLS must match the Zig version that compiles the project; a version mismatch shows up as missing completions or a server that exits at startup.

C and C++ files in a Zig project are served by clangd like any C/C++ project; ZLS does not serve them. See [C and C++](/en/languages/cpp).

## Zig toolchain

**Settings › Languages & Frameworks › Zig** selects the Zig installation used for **External Libraries**:

- **Zig toolchain**: the directory holding `zig`. **Auto** uses `zig` on `PATH`. PATH, Homebrew, zvm and mise / asdf installs are detected; **Browse** picks another directory.
- The selected version is shown next to the field. External Libraries use this directory; run configurations and ZLS look up `zig` on `PATH`, so keep the project's Zig on `PATH` too (or select that same installation here).

## Run and test

Run configurations are detected from `build.zig`:

- `zig build` for the default step.
- `zig build <step>` for every top-level step (`install` and `uninstall` are left to the default build). Steps named `test`, `test-*` or `test_*` are test configurations and report to the test tree.
- An executable for every `addExecutable` target: it is built first and starts the installed binary from `zig-out/bin`, so **Run** works without a separate build step.

**Run Context Configuration** (`⌃⇧R` / `Ctrl+Shift+F10`) on a `.zig` file runs it. Failures from `zig build test` and `zig test` are parsed into the test tree, and **Rerun Failed Tests** narrows a failed test with `--test-filter`.

## Debugging

Zig applications run under **CodeLLDB**. Debugging an executable configuration builds it first, then starts the binary with CodeLLDB, so breakpoints in Zig, C and C++ sources work. Install CodeLLDB from **Settings › Languages & Frameworks › Language Servers**. See [Debugging](/en/guide/debugging).

## Limitations

- The Zig toolchain setting drives External Libraries and version discovery, not the `zig` that run configurations and ZLS use; those look up `PATH`.
- ZLS must match the Zig version that compiles the project. The IDE does not download a matching pair.
