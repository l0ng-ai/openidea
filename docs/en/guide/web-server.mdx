---
title: Web Server Mode
description: Run OpenIDEA in a web browser on a configurable host and port, directly or behind a reverse proxy.
---

OpenIDEA can run as a headless web application using `openidea-server --web`. The server hosts the built frontend assets and exposes the full Rust IDE backend (files, search, LSP code intelligence, integrated terminal, Git, run/debug, settings) over a single HTTP + WebSocket port.

## Build

Build both the frontend bundle and `openidea-server`:

```bash
pnpm install
pnpm build
cargo build --release -p ide-host --bin openidea-server
```

## Run

The quickest way to launch the web IDE (from a repo checkout or inside a container) is the standalone launcher script:

```bash
./scripts/start-web.sh
```

It listens on `0.0.0.0:8080` by default (configurable via `OPENIDEA_HOST` / `OPENIDEA_PORT`), auto-detects the `openidea-server` binary, the built `dist/` folder, and the workspace directory, and stores persistent settings and caches inside `<workspace>/.openidea-server`.

Or invoke `openidea-server --web` directly on any host and port (default: `127.0.0.1:8080`):

```bash
./target/release/openidea-server --web \
  --host 0.0.0.0 \
  --port 8080 \
  --web-dir ./dist \
  --project /path/to/workspace
```

Then open `http://localhost:8080/` in a browser.

## CLI Options & Environment Variables

| Flag                     | Environment Variable     | Default                    | Description                                                                 |
| ------------------------ | ------------------------ | -------------------------- | --------------------------------------------------------------------------- |
| `--host <addr>`          | `OPENIDEA_HOST`          | `127.0.0.1`                | Bind address (use `0.0.0.0` inside containers)                              |
| `--port <port>`          | `OPENIDEA_PORT`          | `8080`                     | TCP port for HTTP and WebSocket traffic                                     |
| `--base-path <prefix>`   | `OPENIDEA_BASE_PATH`     | _(auto)_                   | Optional reverse-proxy URL prefix                                           |
| `--web-dir <dir>`        | `OPENIDEA_WEB_DIR`       | auto-detected `dist/`      | Built frontend directory                                                    |
| `--project <path>`       | `OPENIDEA_WORKSPACE_DIR` | _(none)_                   | Workspace folder opened automatically on startup                            |
| `--home <dir>`           | `OPENIDEA_SERVER_HOME`   | `~/.openidea`              | Persistent directory for settings, indexes, and caches                      |
| `--token <secret\|auto>` | `OPENIDEA_WEB_TOKEN`     | _(disabled)_               | Require an access token (`auto` generates a random token)                   |
| `--no-trust-project`     | —                        | _(auto-trust `--project`)_ | Prompt for trust confirmation instead of trusting `--project` automatically |

## Reverse Proxy & Subpath Deployments

OpenIDEA web mode uses relative asset URLs and relative WebSocket resolution (`api/ws`), and automatically resolves static assets and API endpoints whether a reverse proxy strips its path prefix or forwards the full prefix untouched:

- **Direct access**: `http://localhost:8080/`
- **Prefix-stripping proxy**: `https://proxy.example/ide/` → backend receives `/` and `/api/ws`
- **Prefix-preserving proxy**: `https://proxy.example/user/session/123/` → backend receives `/user/session/123/` and `/user/session/123/api/ws`

### Health Endpoint

`GET /api/health` (also reachable under any proxy prefix, e.g. `.../api/health`) returns `200 OK` with JSON status without requiring authentication, suitable for container readiness and liveness probes.

## Authentication

When running directly on a reachable network without an authenticating reverse proxy in front, enable token authentication:

```bash
openidea-server --web --host 0.0.0.0 --port 8080 --token auto
```

The server prints a login URL containing `?token=...` (which sets an `HttpOnly; SameSite=Lax` cookie and redirects to strip the token from the URL) and serves a sign-in form for unauthenticated visitors. When running behind a platform reverse proxy that already authenticates requests, omit `--token` (or pass `--no-auth`).

## Persistent Storage & Containers

In ephemeral container environments, point `OPENIDEA_SERVER_HOME` at a mounted persistent volume (for example inside your mounted workspace directory) so settings, recent projects, and indexes survive restarts. The included launcher script [`scripts/start-web.sh`](https://github.com/luisfelipe18/openidea/blob/main/scripts/start-web.sh) does this automatically when `OPENIDEA_WORKSPACE_DIR` is set.

Build and run with Docker:

```bash
docker build -f Dockerfile.web -t openidea-web .
docker run --rm -p 8080:8080 -v "$PWD:/workspace" openidea-web
```
