OpenIDEA 内置 Git 支持，Git 也是它唯一支持的版本控制系统。

仓库状态（状态、差异、Blame、日志）在进程内读取；所有修改仓库的操作都调用 `git` 可执行文件完成，因此钩子、凭据、签名和你的 Git 配置都和命令行下的行为一致。你需要先安装 Git。OpenIDEA 依次在 `OPENIDEA_GIT`、`PATH` 和常见安装位置中查找；也可以在 **设置 › 版本控制 › Git › Git 可执行文件路径** 中指定路径，并点击 **测试** 检查。

## 获取仓库

- **Git › 克隆…** 打开 **克隆仓库**。填写 **URL：** 和 **目录：**，需要时勾选 **浅克隆，历史记录截断为** N 个提交。侧栏中的 **GitHub** 会列出你的 GitHub 仓库（见 [GitHub](/zh/guide/github)）。
- 克隆时默认包含嵌套子模块。如只需克隆主仓库，可在 **设置 › 版本控制 › Git** 中关闭 **递归克隆子模块**。
- 对于浅克隆，可以在 **Git** 菜单或 **日志** 标签页选择 **获取完整历史**，下载缺失的提交。
- 新建项目时，在新建项目对话框中勾选 **创建 Git 仓库**。
- **Git › 创建 Git 仓库…** 会在你选择的目录（默认是项目根目录）里执行 `git init`，并立即注册这个新仓库；在终端里创建的仓库同样会被识别。

OpenIDEA 会找到包含项目的仓库，以及向下最多四层的嵌套仓库（跳过 `node_modules`、`target`、`build` 等目录）。状态、提交、获取和更新覆盖所有仓库；分支弹窗中的分支操作同样覆盖所有仓库（见[分支](#分支)）；日志操作针对所选仓库。子模块显示为嵌套仓库。更新项目时，可以随父仓库一起更新处于分离 HEAD 的子模块。

## 提交更改

**提交** 工具窗口按组列出更改：**合并冲突**、**更改**（每个更改列表一组）和 **未跟踪的文件**。选择 **视图选项 › 分组依据 › 暂存状态** 后，更改会分为 **已暂存的更改** 和 **未暂存的更改**。

<Steps>
  <Step title="选择要提交的内容">
    勾选要包含的文件。未跟踪的文件和冲突默认不勾选，并且只勾选活动更改列表中的更改。`Space`
    切换所选项。部分暂存的文件只包含已暂存的代码块。
  </Step>
  <Step title="填写提交消息">
    在消息框中输入。**提交消息历史记录** 按钮（或 `⌃M` / `Ctrl+M`）提供最近 20 条消息。合并、拣选或还原过程中，消息会从
    Git 预先填入；其他情况下使用 `commit.template`。
  </Step>
  <Step title="提交">
    点击 **提交**，或在消息框中按 `⌘Enter` / `Ctrl+Enter`。**提交并推送…**（在消息框中按 `⌥⌘Enter` /
    `Ctrl+Alt+Enter`）会在提交后推送。
  </Step>
</Steps>

勾选 **修改**（`⌃⌥M` / `Alt+M`）可以修正上一次提交，按钮会变为 **修正提交**。

双击文件（或按 `Enter`）查看差异；**预览差异** 会在树旁边直接显示。文件右键菜单包括 **显示差异**、**跳转到源代码**、**回滚…**、**添加到 VCS**、**添加到 .gitignore**、**暂存**、**取消暂存**、**移动到其他更改列表…**、**搁置更改…**、**创建补丁…**、**以补丁形式复制到剪贴板**、**显示历史记录**、**显示本地历史记录** 和 **使用 Git Blame 注解**。

### 部分提交

只想提交文件的一部分时，从提交工具窗口打开它的差异。用边栏的 **包含在提交中** 复选框选择整个变更块。要具体到单行，在并排或统一视图中选中这些行，然后使用右键菜单中的 **提交所选行** 或 **从提交中排除所选行**。在统一视图中，可拖过删除行和新增行一次选中两侧的改动。树中的复选框会显示部分选中的状态。OpenIDEA 通过临时索引提交选中的内容，保留工作区文件和其他已暂存的改动。

习惯使用暂存区的话，差异工具栏里也有 **暂存更改 (git add hunk)**。

### 更改列表

更改列表用来给本地更改分组，不影响 Git。默认列表名为 **更改**，新的更改进入活动列表。更改列表按项目保存在 `.openidea/changelists.json` 中。

- **新建更改列表…**、**编辑更改列表…**（`F2` 或 `⇧F6` / `Shift+F6`）、**删除更改列表**、**设置活动更改列表**。
- **移动到其他更改列表…**（`⇧⌘M` / `Alt+Shift+M`），或者直接在列表之间拖动文件。
- 右键某个更改列表选择 **提交…**，只提交这个列表。

### 提交选项与检查

**提交** 按钮旁的齿轮按钮（**提交选项**）包含：

- **作者:**：以其他身份提交（`Name <email>`），以及 **签署提交**。
- **提交检查**：**重新格式化代码**、**优化导入**、**清理**（应用 fix-all 代码操作）和 **运行 Git 钩子**（关闭时加 `--no-verify`）。
- **高级提交检查**：**分析代码**（语言服务器报告的错误和警告）和 **检查 TODO**（检查改动行是否匹配 **设置 › 编辑器 › TODO** 中的规则）。

在 **设置 › 编辑器 › TODO** 中创建命名筛选器，再通过 **检查 TODO** 旁的 **配置** 选择要检查的模式组。提交工具窗口和 TODO 工具窗口分别按项目保存选择。点击 **查看 TODO** 会在 TODO 工具窗口打开结果标签页，可以浏览全部匹配项和检查时的内容，并跳转到对应源码或差异。若所选文件无法检查，结果会列出文件和原因，便于处理后重试。

在提交工具窗口选择运行配置，再开启 **运行测试**，即可将其加入高级检查。配置选择保存在本地，按项目生效。测试针对当前工作树运行，可能包含本次未选中的改动。点击 **查看运行输出** 可打开失败的运行。

开启 **提交后运行高级检查** 后，本地提交完成后会在后台运行代码分析、TODO 检查和测试。推送对话框会显示待推送提交的检查状态。**提交并推送** 和 **运行提交检查** 会等待已启用的检查完成。

提交前，OpenIDEA 还会对以下情况发出警告：在分离 HEAD 或变基过程中提交、文件名在其他系统上可能有问题、文件大于 50 MB、CRLF 换行符。出现警告时第一次提交会被拦下，点击 **仍然提交** 继续。

### 使用 GPG 为提交签名

在受信任的项目中打开 **设置 › 版本控制 › Git › 配置 GPG 签名**。选择仓库，开启 **使用 GPG 为提交签名**，然后选择 OpenPGP 签名密钥。OpenIDEA 将设置保存到所选仓库的 Git 配置，后续提交使用该仓库配置的签名程序。

### 模态提交

在 **设置 › 版本控制 › 提交** 中关闭 **使用非模态提交界面** 后，就没有提交工具窗口了：**本地更改**、**搁置** 和 **贮藏** 变成 Git 工具窗口的标签页，**提交…** 会打开 **提交更改** 对话框。

## 编辑器中的更改标记

编辑器边栏会标出相对于 HEAD 新增、修改和删除的行。点击标记会弹出窗口，提供 **上一个更改**、**下一个更改**、**回滚**、**显示差异** 和 **复制原始文本**。光标位于已更改的行上时执行 **回滚…**，只回滚这些行。

## 回滚、添加与忽略

- **回滚…** 打开 **回滚更改**：选择文件，可选 **删除已添加文件的本地副本**。
- **添加到 VCS** 添加未跟踪的文件。新建或删除文件时，OpenIDEA 会询问是否在 Git 中添加或删除；可在 **设置 › 版本控制 › 确认** 中修改。
- **添加到 .gitignore** 把规则写入最近的 `.gitignore` 或 `.git/info/exclude`。

## 差异查看器

差异在编辑器标签页中打开。

| 下一个 / 上一个差异 | `F7` / `⇧F7`  | `F7` / `Shift+F7`          |
| 下一个 / 上一个文件 | `⌃⇧→` / `⌃⇧←` | `Alt+Shift+Right` / `Left` |
| 接受左侧            | `⌃⌘→`         | `Ctrl+Alt+R`               |
| 接受右侧            | `⌃⌘←`         | `Ctrl+Alt+A`               |
| 跳转到源代码        | `F4` 或 `⌘↓`  | `F4`                       |

工具栏可以在 **并排查看器** 和 **统一查看器** 之间切换，并设置空白处理（**不忽略**、**修剪空白**、**忽略空白**、**忽略空白和空行**）、高亮方式（按词、按行或不高亮）、**折叠未更改的片段**、**同步滚动** 和 **对齐更改**。右侧是工作区文件时可以直接编辑，也可以 **还原更改** 或 **暂存更改 (git add hunk)**。边栏中的箭头可以把一侧的更改应用到另一侧。

其他比较方式：

- **比较对象…**（在项目视图中按 `⌘D` / `Ctrl+D`）、**比较文件**、**比较目录**（可向左/向右复制）和 **视图 › 与剪贴板比较**。

## 分支

点击标题栏的分支微件（或 **Git › 分支…**）打开分支弹窗，输入文字即可搜索分支和操作。弹窗中有 **最近**、**本地**、**远程** 和 **标签** 分组，顶部有 **更新项目…**、**提交…**、**推送…**、**新建分支…** 和 **签出标签或修订…**。齿轮按钮可以切换按前缀分组、显示最近分支和显示标签。

**签出标签或修订…** 会建议目标仓库共有的分支和标签，也支持输入提交哈希或修订表达式。开启分支同步后，顶层操作会在各仓库中将 HEAD 分离到所选修订。从某个仓库的子菜单打开时，操作只作用于该仓库。

点击标题栏分支名旁的传入或传出标记（或分支弹窗中的 **传入和传出的提交…**）即可列出待拉取或待推送的提交（最新的在前）。点击某个提交查看其差异，或点 **在 Git 日志中打开** 在 Git 日志中显示它。

选中分支（`→` 或 `Enter`）查看它的操作：

- **签出**、**从 '…' 新建分支…**、**签出并变基到 '…'**
  （变基结束或中止后恢复本地改动）
- **与 '…' 比较**在编辑器中打开双面板 Git 日志。两侧各有独立的筛选和提交详情。点击 **显示分支差异** 可查看两个分支之间的文件差异。分支菜单还提供 **显示与工作树的差异** 和 **显示历史记录**。
- **将 '…' 变基到 '…'**、**将 '…' 合并到 '…'**；远程分支还有 **使用变基拉取到 '…'** / **使用合并拉取到 '…'**
- **更新**、**推送…**、**重命名…**、**添加到收藏夹**、**删除**

如果本地更改阻止签出，可以选择 **智能签出**（贮藏、签出、再恢复）、**强制签出** 或 **不签出**。删除的分支可以通过通知中的 **恢复** 找回。

有多个仓库时，弹窗会显示所有仓库共有的分支，以及每个仓库各自的子菜单；对公共分支的操作（签出、签出并变基、变基、合并、更新、重命名、删除等）会在每个仓库中执行，如果在某个仓库失败，OpenIDEA 会提议回滚其他仓库。各仓库处于不同分支时，弹窗会提示**分支已分叉**，但仍列出公共分支，检出其中一个即可让各仓库回到同一分支。在 Git 设置中关闭**在所有仓库执行分支操作**后，弹窗只列出并操作所选仓库。

## 与远程同步

- **获取** 会获取所有仓库。OpenIDEA 还会在后台检查传入的提交，依次获取每个分支有上游的仓库（打开项目 20 秒后检查一次，之后默认每 15 分钟一次），见 Git 设置中的 **显式检查远程上的传入提交** 和 **检查传入提交的间隔**。
- **更新项目…**（`⌘T` / `Ctrl+T`）以合并或变基方式拉取所有仓库，未提交的更改会先贮藏再恢复。只有开启 **更新前显示选项** 时才会显示 **更新项目** 对话框。
- **拉取…** 把选定的远程分支拉取到当前分支，可选 `--rebase`、`--ff-only`、`--no-ff`、`--squash` 等选项。
- **推送…**（`⇧⌘K` / `Ctrl+Shift+K`）列出待推送的提交及其文件。可以修改目标分支、选择远程，并选择 **强制 (with lease)**、**设置上游** 或推送标签。受保护分支（默认 `master; main`）禁止强制推送。推送被拒绝时，OpenIDEA 会提供合并或变基后重新推送。
- **管理远程…** 添加、编辑和删除远程。

HTTPS 密码和 SSH 口令通过对话框询问，可以选择记住；保存的 HTTPS 凭据列在 **设置 › 版本控制 › Git › 密码** 中。

## 合并、变基与冲突

**Git › 合并…** 和 **Git › 变基…** 打开对话框，提供常用的 Git 选项（`--no-ff`、`--ff-only`、`--squash`、`--no-commit`；`--onto`、`--rebase-merges`、`--keep-empty`）。合并、变基、拣选或还原进行中时，标题栏会显示一个微件，提供 **解决冲突…** 以及继续 / 中止；Git 菜单中的 **中止合并**、**继续变基**、**跳过提交**、**中止变基** 以及拣选、还原对应的操作也会变为可用。合并通过提交来完成。

在 **Git › 变基…** 中，从 **修改选项** 启用 `--interactive` 即可编辑重放计划。在线性计划中，选择 **改写** 后，可以在开始变基前从详情区域编辑提交消息。OpenIDEA 会在 Git 重放到对应提交时应用改写后的消息，解决冲突后从 IDE 继续变基时也一样。包含合并指令的计划会在文本编辑器中打开。

出现冲突时，通知和 **冲突** 对话框会列出相关文件。对每个文件选择 **接受您的**、**接受他们的** 或 **合并…**。

Git 操作暂停期间，冲突对话框会保留未解决和已解决的文件。可在对话框或提交视图中选择 **回退已解决的冲突** 重新打开选中的文件。检查结果后再继续操作或提交合并。

**合并…** 打开三方合并编辑器：左侧是你的版本，中间是结果，右侧是他们的版本。

- 点击边栏中的箭头接受某处更改，点叉号忽略它。按住修饰键可以用某一侧解决整个冲突。
- 工具栏可以应用所有不冲突的更改（左侧、右侧或两侧）、**解决简单冲突**、任意比较其中两个版本，并显示剩余的更改和冲突数。
- 点击 **应用** 保存编辑后的文本结果并标记为已解决。**接受您的** 和 **接受他们的** 会采用所选一侧的完整版本，包括二进制内容、文件模式或删除操作。二进制合并视图也提供这两个选项。

带冲突标记的文件顶部会显示横幅和 **解决冲突…**，冲突标记也会作为错误报告。在文本编辑器中，**接受您的（光标处的冲突）**、**接受他们的（光标处的冲突）**、**全部接受（光标处的冲突）** 可以逐个解决冲突。

## Git 日志

Git 工具窗口的 **日志** 标签页显示提交图。

- **过滤**：文本或哈希（支持正则和区分大小写）、分支、用户、日期和路径；**最近使用的过滤条件** 可以找回之前的过滤。
- **转到哈希/分支/标签**（在日志中按 `⌘F` / `Ctrl+F`）。
- **图形选项**：按日期、拓扑或传入优先排序；仅第一父提交；不显示合并提交。
- **视图选项**：引用显示方式、详情面板，以及列（**作者**、**日期**、**哈希**、**签名**、**GitHub 提交检查**）。
- **视图选项 › 高亮 › 未拣选的提交**：选择源分支，或使用日志当前筛选的分支。日志会淡化已进入签出分支的提交，方便查看仍待拣选的提交。在分支比较中，每个面板以另一侧的分支为比较目标。
- 左侧的分支面板可以按分支过滤日志，并提供分支操作。选中多个本地分支后选择 **Update Selected**，会把每个分支快进到它的跟踪分支，每个远程只 fetch 一次；结果汇总在一条通知里，列出已更新的分支，以及因不能快进或没有跟踪分支而未更新的分支。
- 有多个仓库时，分支面板中每个分支只列一次；只存在于部分仓库的分支，后面会以灰字列出这些仓库，对它的操作会在这些仓库中执行。点击面板工具栏中的**按仓库分组**，可改为每个仓库一棵子树。
- 详情面板显示变更文件、提交消息、提交者、包含该提交的分支以及签名。
- 将鼠标悬停在 **签名** 列的图标上，可查看验签结果，以及可用的签名者和密钥指纹。更改验签密钥或信任设置后，点击日志工具栏的 **刷新** 重新验签。

右键提交可以选择 **复制修订号**（`⌥⇧⌘C` / `Ctrl+Alt+Shift+C`）、**创建补丁…**、**拣选**、**签出修订**、**显示此修订版本的仓库**、**与本地比较**、**将当前分支重置到此处…**、**还原提交**、**撤消提交…**、**新建分支…**、**新建标签…**、**在浏览器中查看** 等。选中两个提交时，**比较版本** 会比较它们。提交列表获得焦点时，`F2` 编辑提交消息，`⌥⌘N` / `Ctrl+Alt+N` 新建分支，`←` / `→` 跳到子提交或父提交，`F3` / `F11` 切换提交书签（`⌥F3` / `Ctrl+F11` 带助记符）。

### 改写历史

在日志中可以 **编辑提交消息…**、**修补提交…**、**压缩到…**、**丢弃提交**、**压缩提交…** 和 **从此处进行交互式变基…**。交互式变基对话框可以对提交执行 pick、reword、edit、squash、fixup、drop，并调整顺序。这些操作也可以用于已推送的提交：改写前会先确认，之后推送需要强制推送。受保护分支上已推送的提交不能被改写。

日志中的 **从此处进行交互式变基…** 要求提交范围是线性的。**撤消提交…** 可用于最新的提交，并将其更改放回更改列表。

在更改文件窗格里选择 **应用所选更改**，可将选中文件的变更应用到工作区。
选择提交中的部分文件后，可用 **提取所选更改** 将这些文件的变更移到紧接原提交的新提交中。分支末端的文件内容、本地修改和暂存区都会保留。HEAD 仍指向改写后的末端时，可以从成功通知中撤销提取。
用 **移除所选更改** 可从该提交移除这些文件的变更，再重放后续提交。遇到冲突时可以解决后继续变基，也可以中止以恢复原历史。操作直接完成后可从通知中撤销。

### 标签、重置与工作树

- **Git › 新建标签…** 在某个提交上创建标签（填写消息时为附注标签）。日志中的 **新建标签…** 创建轻量标签。
- 标签菜单的 **推送到** 列出已配置的远程，包括尚无跟踪分支的远程。删除本地标签后，**恢复** 可重建原标签。**在远程删除** 只会删除仍指向原提交或原附注标签对象的远程标签。
- **Git › 重置 HEAD…** 和 **将当前分支重置到此处…** 支持 **软**、**混合**（默认）、**硬** 和 **保留** 四种模式。
- 从 **Git › 新建工作树…** 或分支、标签的菜单创建工作树。选择 **创建并打开** 会在独立窗口打开它。
- 在 **新建工作树** 中选择 **创建 .worktreeinclude…** 或 **编辑 .worktreeinclude…**，打开所选仓库的配置文件。每行写一条 Git 忽略规则。编辑器横幅可将 OpenIDEA 项目设置和运行配置加入现有文件。点击 **返回新建工作树** 会保存文件，并保留已选的分支和路径。勾选 **复制 .worktreeinclude 中列出的本地文件** 后，匹配的本地文件会复制过去，新工作树中已有的文件会保留。
- 选中 **运行初始化脚本** 并选择项目所在主机上的可执行脚本。脚本在配置复制完成后运行，以新工作树为工作目录，首个参数也是新工作树路径。**跳过初始化** 会停止脚本并保留工作树。脚本失败或超时也会保留工作树。
- **Git › 工作树…** 打开 **工作树** 标签页，可在这里打开、锁定、解锁、移动或移除工作树。同一仓库的工作树可以多选后一起移除。用 **清理工作树…** 可清理目录已缺失的 Git 记录。

## 贮藏、搁置与补丁

**贮藏** 使用 `git stash`：

- **贮藏更改…**：填写消息，可选 **保留索引** 和 **包括未跟踪的文件**，贮藏整个工作区；更改树右键菜单中的 **贮藏所选文件…** 只贮藏选中的文件。
- **取消贮藏更改…**：应用或弹出某个贮藏，恢复索引，或基于它新建分支。
- **Git › 未提交的更改 › 显示储藏** 打开储藏列表。右键选中的储藏可以应用、弹出或丢弃它，也可以用 **恢复储藏为…** 设置恢复选项，或用 **清空储藏…** 清空它所属仓库的储藏。
- 选择储藏后，可在相邻的文件窗格中查看更改，包括一并保存的未跟踪文件。可选择一个或多个文件查看差异、与本地文件比较，或使用 **应用所选更改** 仅恢复选中的更改并保留储藏。

**搁置** 由 IDE 管理，以补丁形式保存在 `.openidea/shelf` 中：

- **搁置更改…**：选择文件并命名，之后这些更改会被还原。
- **取消搁置…**：以三方合并的方式把搁置（或其中某个文件）应用到你选择的更改列表。
- **静默搁置**（`⇧⌘H` / `Ctrl+Shift+H`，也在更改工具栏上）不弹对话框，直接搁置选中的更改（未选中时为活动更改列表）：每个更改列表一个搁置，以列表名命名。**静默取消搁置**（在搁置中按 `⌥⌘U` / `Ctrl+Alt+U`）把选中的搁置或文件应用到与搁置同名的更改列表，没有则应用到活动更改列表。
- **搁置** 标签页列出所有搁置，支持查看差异、与本地比较、导出补丁、重命名和删除。

在 Git 设置中打开 **在同一个标签页中合并显示贮藏和搁置**，两者会显示在同一个标签页里。

**Git › 补丁** 包含 **创建补丁…**、**应用补丁…** 和 **从剪贴板应用补丁…**。

## Blame 与历史

- **使用 Git Blame 注解** 在边栏中逐行显示作者和日期（也可以从边栏右键菜单打开）。点击某条记录会在日志中打开对应提交。在 Git 设置中打开 **为当前行显示内联 Git Blame**，会在光标所在行末尾显示作者；点击它会打开对应提交，关闭 **点击内联 Git Blame 时打开提交** 后则不会。
- 注解行的右键菜单中，**标注上一版本** 会打开该提交之前版本的文件（已注解），与这个提交的版本并排显示。
- **标注指定版本…** 可选择文件的任意版本，把该版本（已注解）与工作区文件并排显示。
- **显示历史记录** 在 Git 工具窗口的标签页中打开文件历史。
- **显示所选内容的历史记录** 列出修改过所选行的提交。
- **显示当前修订版** 在日志中定位光标所在行的提交。

注解会跳过 `blame.ignoreRevsFile` 指向的文件（约定是仓库根目录下的 `.git-blame-ignore-revs`）中列出的提交，因此一次格式化或批量重命名的提交不会认领所有行。在注解行的右键菜单中选择 **忽略此提交**，会把当前行的提交加入该文件并刷新注解。

### 本地历史记录

本地历史记录独立于 Git 保存文件快照，包括已删除的文件，以及重构前自动记录的状态等带标签的快照。

- **Git › 当前文件 › 本地历史记录**（或项目视图中的 **本地历史记录 › 显示历史记录**）打开文件或文件夹的历史。选中某个版本后点击 **还原**（已删除的文件为 **恢复**）。
- **添加标签…** 给当前状态打标记。
- **最近的更改**（`⌥⇧C` / `Alt+Shift+C`）列出整个项目最近的编辑。

保留策略在 **设置 › 外观与行为 › 系统设置** 的 **本地历史记录** 部分设置：默认保留 5 个工作日、每个项目 512 MB。超过 2 MB 的文件不会自动保存快照。

## 设置

**设置 › 版本控制** 包含以下页面：

| 页面         | 主要选项                                                                                                                                                               |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **提交**     | 非模态提交界面、提交后清空消息、提交消息检查（主题与正文之间空行、主题和正文长度、右边距）、默认提交检查。                                                             |
| **确认**     | 新建或删除文件时的处理方式、**更新前显示选项**、丢弃提交前确认、在项目视图中高亮包含修改的目录、历史记录行数上限。                                                     |
| **目录映射** | 添加和移除 Git 仓库映射，或将自动检测到的仓库排除在 Git 集成之外。                                                                                                     |
| **问题导航** | 把提交消息中的问题编号变成链接的正则规则（内置 JIRA、YouTrack 和 GitHub 预设）。                                                                                       |
| **日志**     | 引用和时间的显示方式、显示哪些列。                                                                                                                                     |
| **搁置**     | 应用后从搁置中移除文件。                                                                                                                                               |
| **Git**      | Git 可执行文件、内联 Blame、提交警告、默认签署、推送选项和受保护分支、更新方式（合并或变基）、传入提交检查、已保存的密码、合并显示贮藏和搁置、在所有仓库执行分支操作。 |
| **GitHub**   | 见 [GitHub](/zh/guide/github)。                                                                                                                                        |

## 暂不支持

- Mercurial、Subversion、Perforce 等其他版本控制系统。
- 除大文件警告外的 Git LFS 支持。
