路线图只写方向和完成标准，不承诺具体日期。每个里程碑完成后会在[更新日志](/zh/changelog)中说明。

## 里程碑 1

### 1. 语言能力

在当前架构下（LSP、DAP 加上 IDE 自己的索引），把主流商业 IDE 覆盖的语言和框架尽力做到可用：

| 方向     | 语言与框架                            |
| -------- | ------------------------------------- |
| JVM      | Java、Kotlin、Spring                  |
| Python   | Python、Django、Flask                 |
| Go       | Go                                    |
| Web      | JavaScript、TypeScript 及主流前端框架 |
| PHP      | PHP、Laravel                          |
| Ruby     | Ruby、Rails                           |
| 系统编程 | C、C++、Rust                          |
| .NET     | C#、.NET、Unity                       |
| 数据     | SQL 与数据库工具                      |

每门语言按同一张清单验收：补全、跳转、查找用法、重构、代码检查、格式化、运行、测试、调试、构建工具、主框架支持。各语言当前的情况见[语言支持总览](/zh/languages/index)。

架构上做不到的能力（例如依赖完整语义模型的结构化搜索、跨语言深度重构）会在对应的语言页里写明。

### 2. 插件生态：SDK 与插件市场

**开发**

- 插件 API 进入稳定期，按语义化版本发布，破坏性变更只在主版本里做。
- 文档完整，API 参考由接口定义自动生成。
- Rust SDK、项目模板和 `openidea-plugin` 命令行覆盖开发、调试、测试、打包的全流程。

**发布**

- 作者自助注册发布者、提交新版本，自动检查签名、兼容性和包内容，审核规则公开。
- 安全：签名校验、权限展示、吊销与密钥轮换（已具备），并补充恶意插件的举报与下架流程。

**发现与安装**

- 搜索、分类筛选，插件详情包含 README、截图、更新记录、所需权限和兼容版本。
- 网页版市场：不打开 IDE 也能浏览插件，并一键在 IDE 中安装。

**生态**

- 官方插件作为 API 示例覆盖各个扩展点，并扶持第一批社区插件上架。

完成标准：第三方作者只看文档就能做出语言插件、工具窗口插件或主题插件并发布到市场，用户能在 IDE 或网页上找到并安装，整个过程不需要改宿主代码。

### 3. 基础 Agent 支持

- 接入 ACP 协议的 Agent，支持用户自定义添加。
- 对话面板，能把选区、文件、问题列表等作为上下文发给 Agent。
- Agent 的改动以 diff 形式展示，用户审阅后应用；工具调用需要用户授权。
- 内置 MCP Server，让外部 Agent 能调用 IDE 的代码智能、运行和调试能力。

完成标准：主流 Agent 能在 IDE 内完成「提需求 → 改代码 → 审阅 diff → 运行测试」的完整流程。

## 暂不做

- **兼容 IntelliJ 平台插件**：插件模型不同，无法直接加载。主题可以导入（见[主题与字体](/zh/guide/themes)），其他插件需要移植到 OpenIDEA 的插件 API。
