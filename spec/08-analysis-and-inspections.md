# 08 — 守护分析与检查

> 范围：编辑期后台分析的触发、调度、增量与结果合入，以及检查/快速修复/意图/注解器/问题视图的模型与契约。｜ 依赖：01、02、03、05、06、07。｜ 排除：解析与结构树（06）、索引（07）、补全与导航（09）、重构与生成（10）、整仓离线检查报告（21）。

## 1. 目的与范围

### 1.1 本子系统解决什么问题

用户在编辑器里每敲一个键，系统必须在**不阻塞输入**的前提下回答四个问题：文本有无语法错误、每个符号指向什么、有哪些可配置的质量问题、光标处能做哪些变换。这四个答案都依赖解析与索引（见 06、07），而它们在每次编辑后立即失效。

本子系统给出的答案是**守护分析（Daemon Analysis）**：一条常驻的、以文档版本为输入、以可丢弃结果为输出的增量流水线。设计要点不是"算得全"，而是：**结果永远可丢弃**（绑定输入版本，版本不符即丢弃，不作修补）；**计算永远可取消**（用户继续输入时正在跑的分析必须让路，取消是正常路径）；**呈现永远渐进**（先可见区域后整文件，先词法/语法后语义/检查/外部工具）；**失败永远局部**（一个检查或注解器崩了，只损失它自己的产出）。

### 1.2 边界

**不负责**：解析与结构树构建、桩生成（见 06，只消费其产物）；索引的建立、持久化与失效判定（见 07，只订阅就绪/失效）；文档编辑、撤销、写命令语义（见 05，只读版本号并在写命令内执行修复）；像素级渲染、主题、字体（见 13，只产出"区间 + 严重度 + 属性键"）；整项目离线检查报告与 CI 集成（见 21）。

### 1.3 与其他子系统的关系

| 关系 | 说明 |
|---|---|
| 05 文档与编辑器 | 提供文档、修改戳、可见区间、写命令；结果以标记形式交回 |
| 06 解析与语法树 | 提供结构树、元素访问器、注入片段；遍在结构树上行走 |
| 07 索引 | 提供跨文件事实；索引版本变化整体标脏分析结果 |
| 03 运行时并发 | 提供读锁/写意图、进度凭证、取消语义、工作池与优先级 |
| 09 补全与导航 | 消费引用高亮与意图列表 |
| 13 界面 | 提供状态区指示器、问题视图停靠区、设置界面 |
| 15 扩展机制 | 检查、意图、注解器、遍工厂均以扩展点接入 |

## 2. 概念模型

### 2.1 术语

| 术语 | 定义 |
|---|---|
| 分析会话（Analysis Session） | 针对某个文档版本的分析上下文：文件、版本、代际、进度凭证、颜色方案、最低严重度阈值 |
| 高亮遍（Highlighting Pass） | 可独立调度、取消、应用的计算单元；有稳定数字标识、作用区间、前驱约束 |
| 高亮条目（Highlight Item） | "区间 + 严重度 + 属性 + 描述 + 修复"的产出，是遍的输出单位 |
| 检查（Inspection） | 可配置的问题检测器，带声明式元数据、选项、抑制规则与修复工厂 |
| 快速修复（Quick Fix） | 针对单个问题的最小变换，由问题产出者附带 |
| 意图（Intention） | 用户显式触发的上下文变换，与问题无绑定关系 |
| 注解器 / 外部注解器 | 遍历式轻量标注器 / 三阶段标注器（收集 → 后台或进程外计算 → 应用） |
| 检查配置（Profile） | "检查标识 → 启用位、严重度、选项"的映射表；有默认、项目、单一检查等形态 |
| 问题记录（Problem Record） | 面向前方问题视图的归一化条目，可来自高亮、外部工具或其他提供者 |
| 代际（Generation） | 分析活动的单调计数；每次重启 +1，旧代际结果一律作废 |

### 2.2 实体关系

**文档 → 分析会话 → 遍图**；遍图包含综合高亮遍、检查遍、外部工具遍、意图遍、行标记遍。前四者产出**高亮条目**（意图遍产出意图描述符），高亮条目派生出**快速修复**与**问题视图集合**；**检查配置**与**抑制规则**只作用于检查遍。基数约束：一个文档同时至多一个活动会话（旧会话被取消即作废）；一个会话拥有一个遍图；一个遍产出零到多条高亮条目；高亮条目至多归属于一个问题组。

### 2.3 四类"事实"的区别（设计上不可混用）

| 概念 | 持久显示 | 可归组 | 可执行 | 触发方式 |
|---|---|---|---|---|
| 高亮条目 | 是（区间标记） | 可（问题组） | 可（携带修复） | 自动 |
| 问题记录 | 是（问题视图） | 是（提供者/文件/分组） | 可（跳转、修复） | 自动或离线 |
| 快速修复 | 否 | 否 | 是 | 用户点击 |
| 意图 | 否（仅在光标处列出） | 否 | 是 | 用户显式触发 |

**规则**：意图**不得**依赖"必须先有一个问题"；修复**不得**要求先建立问题视图记录。二者共同上级是"可执行变换"，但生命周期与触发源不同。

## 3. 数据模型

### 3.1 分析会话与遍

```
AnalysisSession {
  fileId; projectId
  documentVersion: long          // 文档修改戳；会话唯一有效性依据
  generation: long               // 代际；重启 +1
  mode: full | essential | batch // 常规 / 只保语法级反馈 / 离线批量
  minimumSeverity: rank          // 低于此秩的条目在产出侧即丢弃
  restrictRange; priorityRange   // 计算覆盖区间 / 优先区间（通常为可见区域）
  cancelled: bool
}
HighlightPass {
  id: int; name: string          // 全局稳定标识（-1 = 仅有前驱约束）；name 为面向用户的状态文字
  restrictRange; priorityRange?
  startingPredecessors: int[]    // 必须先完成，本遍才可开始
  completionPredecessors: int[]  // 必须先完成且已应用，本遍结果才可应用
  dumbAware: bool; runsOnVisibleAreaOnly: bool
}
```

### 3.2 高亮条目与严重度

```
HighlightItem {
  fileId; range                  // 半开区间；可位于注入片段
  severity: Severity
  attributesKey: AttributeKey?   // 为空表示沿用严重度默认样式
  description: string; tooltip: string?
  fixes: FixRef[]                // 可为空
  group: ProblemGroup?           // 同一问题在多处的归组标识
  afterEndOfLine: bool; passId: int; sessionGeneration: long
}
Severity { name: string; rank: int; displayName: string; switchable: bool }
```

规范严重度秩（数值即证据）：信息 10、文本属性 11、服务器问题 100、信息（旧）200、弱警告 200、警告 300、错误 400。其中"文本属性"只改样式、不表达问题；"服务器问题"是远端侧失败的占位严重度；信息与弱警告同秩，靠名称区分而非秩。**不变量**：秩相同的两个严重度**必须不**互相覆盖；排序用秩，展示用名称。存在"不显示"这一伪级别（非严重度），表达"该检查被关闭"。

### 3.3 检查声明与配置

```
InspectionEntry {
  id: string                     // 字符集 [A-Za-z0-9_.-]+，非空；抑制与配置的主键
  alternativeId: string?         // 兼容标识；抑制匹配时与主标识同权
  displayName: string; groupPath: string[]   // 分组路径用于问题视图与设置界面
  language: string?              // 为空表示与语言无关
  defaultEnabled: bool; defaultSeverity: Severity
  kind: local | global | cleanup // 编辑器内 / 需项目上下文 / 批量清理
  runForWholeFile: bool          // 必须整文件运行（不得只跑可视区间）
  dumbAware: bool                // 索引未就绪时可运行
  preemptible: bool              // 可被更高优先级任务抢占（未声明者按可抢占处理）
  optionsSchema: SchemaRef       // 选项树的结构声明；descriptionSource 为空表示内联描述
  descriptionSource: string?
}
Profile { name; entries: Map<InspectionId, Setting>; isProjectDefault: bool; singleTool: InspectionId? }
Setting { enabled: bool; severity: Severity /* 可为"不显示" */; options: OptionTree }
```

`singleTool` 非空表示"仅此一项"的临时配置（用于"只跑这个检查"的场景）。

### 3.4 问题记录与抑制

```
ProblemRecord {
  key: string                    // 提供者 + 文件 + 行 + 列 + 文本摘要；用于去重
  provider: string; file: FileId?; line: int; column: int   // 位置字段 -1 表示无该信息
  text: string; group: string?; description: string?
  isDuplicateHighlight: bool     // 与他人区间重合的重复高亮
}
Suppression { inspectionId: string; form: comment|annotation|language|fileLevel|identifier; range: Range; redundant: bool }
```

**生命周期**：检查配置与应用级设置持久化；问题记录与分析结果**不持久化**（可重建）；抑制以源码文本形式存在于文件中，**必须**视为文件内容的一部分而非外挂状态。

## 4. 行为契约

### 4.1 触发源与去抖

| 触发源 | 检测方式 | 标脏范围 | 去抖 |
|---|---|---|---|
| 编辑（文档变更） | 文档变更事件 | 变更元素子树，按局部性判定扩展 | 必须去抖，窗口数百毫秒量级 `[推断]` |
| 外部变更（磁盘） | 内容替换 → 文档重载 | 整文件 | 同上 |
| 检查配置/严重度/高亮级别变更；显式重启 | 设置变更通知 / 用户命令 | 全项目已打开文件并重启；或当前文件 | 不去抖 |
| 索引就绪/失效 | 智能模式切换 | 全项目 | 不去抖；失效时降级而非全清 |
| 插件装卸/扩展注册变化；打开关闭编辑器 | 注册表变更 / 编辑器生命周期 | 全项目 / 该文件 | 短去抖或不去抖 |
| 纯光标移动 | 光标事件 | 意图遍与引用高亮遍 | 短去抖 |
| 兜底轮询 | 定时器 | 所有"未最新"的文件 | 由定时器周期约束 |

去抖计时器**必须**在每次编辑时重置；重置**不**取消已进入应用阶段的遍（应用不得中途打断，否则出现半套标记）。编辑后界面**必须**保留上一轮标记直到新结果应用（见 §4.4 缓存复活），不得先清空再重算。用户可对单个文件关闭定时分析或关闭高亮；关闭是**状态**而非删除，恢复时**必须**重算该文件全部遍。

### 4.2 会话、代际与增量作用域

```
restart(reason, scope):
  1. project → 全部文件标脏；file → 该文件整体标脏
  2. 取消所有在飞遍的进度凭证（取消原因 = reason）
  3. 代际 +1，触发一次新分析（受去抖约束）

dirtyScope(change, file):
  1. 整文件替换/外部重载 → 整文件
  2. 取变更区间覆盖的最小完整元素（结构树祖先）
  3. 询问局部性判定器：能否收窄为更小的干净作用域
     （典型：一个声明内部的变化不污染同文件其它声明，也不污染引用方）
  4. 判定失败或返回空 → 退化为整文件；若变更改变"可见标识集"（增删声明）→ 另把依赖方文件加入待分析队列
```

- **取消是正常控制流**：遍内部任何耗时操作**必须**定期检查取消；取消后**不得**产出部分结果进入应用阶段。**废弃判定**：应用前**必须**复核（代际, 文档版本），任一不符 → 丢弃整遍产出并计数，**不得**只丢弃"看起来过期"的条目。
- **重启幂等**：同一 scope 连续重启 N 次，最终状态必须等价于"重启一次后完成分析"，中间轮次产出全部作废；关闭项目时**必须**先取消再释放，取消等待有上限，超限后放弃等待并记录，不得让关闭无限阻塞。
- 遍的 `restrictRange` **必须**取"脏区间 ∪ 需重算区间"，`priorityRange` **必须**取可视区间与之交集；索引层事实变化**必须**按"受影响文件集合"标脏，不得退回全项目全量。
- **禁止**在脏区间计算中用裁剪后的树冒充真实树（会产出错误偏移）：裁剪只允许作用于**遍历入口**，不允许作用于**偏移计算**。

### 4.3 阶段流水线

渲染期的**词法着色**不属守护遍：渲染时按行取词法状态，是"零等待"的第一层反馈，不参与调度、不产出问题。守护遍从结构树开始：

| 序 | 阶段 | 遍 ID | 输入 | 产出 | 前驱关系 |
|---|---|---|---|---|---|
| 1 | 折叠计算（含注入片段折叠） | 1、14 | 结构树 / 注入片段 | 折叠区间 | 无 |
| 2 | 综合高亮：语法元素标注 + 语义解析 + 引用/类型检查 + 注解器 + 无用代码/隐式使用 | 4 | 结构树、索引、部分配置 | 高亮条目 | 无 |
| 3 | 检查运行 | 7 | 结构树、检查配置、索引 | 条目 + 修复 | 默认与 id 4 并行（见串行化开关） |
| 4 | 意图收集 | 3 | 结构树、光标 | 意图描述符 | 开始前需 id 4 完成 |
| 5 | 外部工具标注 | 8 | 文件内容、可见编辑器、配对检查启用态 | 条目 | 开始前需 id 4 完成 |
| 6 | 行标记 / 慢行标记（导航、继承、测试、昂贵导航信息） | 11、13 | 索引 | 行侧标记 | 应用前需 id 4 完成并应用 / 开始前需 id 4 完成 |
| 7 | 后处理：过滤器链、无用代码、抑制冗余 | 融合于 2/4 | 上游条目 | 过滤/降级后的条目 | 紧随产出者 |

**前驱语义（必须区分）**：`startingPredecessors` 指本遍**开始计算**前前驱必须**完成计算**（不要求已应用）；`completionPredecessors` 指本遍结果**可被应用**前前驱必须**完成且已应用**。这一区别保证"高亮先落地，行标记后落地仍与之对齐"。无前驱关系的遍**可以**并行；有前驱关系的遍**必须**等待，等待期间不占用调度槽。同一文件的多遍共享一个进度凭证，跨文件由工作池调度。

**串行化开关**：存在项目级开关决定"检查遍与综合高亮遍并行"还是"检查必须等综合高亮完成"——默认并行，交叉依赖重的语言插件可切串行；切换**必须**只影响调度顺序，不改变结果集合。

### 4.4 结果合入视图

- **按区间替换**：应用一遍结果时只替换"归属于该遍且位于 `restrictRange` 内"的标记；不得清空整层再重建，也不得整文件重绘。
- **界面线程应用**：应用必须投递到界面线程并携带（模态状态、过期条件）；界面繁忙时**可以**延后，延后期间结果必须保持可丢弃。
- **可见性门控**：编辑器不可见（标签页切走）时**可以**跳过应用，但该遍仍必须完成并计入"已完成"，否则完成计数的归零条件永不成立。
- **最新标记**：应用成功后为（文件, 遍 ID, 文档版本）打"已最新"标记；判断"分析是否完成"只看此标记，不看线程状态。所有遍均最新且无在飞遍时广播"分析完成"事件。
- **缓存复活**：上一轮标记按（起止偏移、层、属性）序列化保存；重启后先恢复，再由新结果按区间覆盖。恢复的标记**必须**在版本不符时整体作废，不得按偏移近似平移。

### 4.5 检查启用判定（有序算法）

```
enabledInspections(file):
  1. profile := 文件级覆盖配置（若存在）否则 项目配置
  2. 候选 := profile 全部条目
  3. 过滤：语言/项目类型适用性；内部检查在非内部模式跳过
  4. 过滤：enabled == true 且 severity != 不显示
  5. 过滤：全局类检查仅在其提供了"编辑器内可用部分"时进入本地候选
  6. 过滤：哑模式下非哑感知检查跳过；文件不可索引时跳过依赖索引的检查
  7. 过滤：文件级抑制命中 → 跳过；语言抑制器声明被抑制（在元素粒度再判一次）
  8. 按"分组路径 + 标识"稳定排序后返回
```

- 判定**必须**是纯查询，不得实例化检查实现（实例化延迟到真正运行，且失败隔离）。同一文件上，检查遍历**必须**共享一次结构树遍历入口（按"接受元素类型"分发），不得每检查各走一次全树。
- `runForWholeFile` 的检查**必须**忽略 `restrictRange`，但仍受 `priorityRange` 影响调度次序。检查可见性级别（错误/警告/全部/无）是**编辑器视图状态**，与配置启用位正交：级别过滤发生在产出侧之前，且不得改变"已最新"标记。

### 4.6 抑制模型

| 形式 | 载体 | 粒度 | 说明 |
|---|---|---|---|
| 注释指令 / 范围抑制 / 文件级抑制 | 文件内容中的注释 | 元素、区间或文件 | 目标为"下一条语句/下一个元素"、注释对之间，或整文件 |
| 注解标注 | 语言元素自身的元数据 | 元素 | 依赖语言注解语义 |
| 语言级抑制器 / 标识符级未抑制 | 语言扩展 / 扩展声明 | 元素 / 标识符 | 语言插件给出的额外抑制判定；或反向解除其它抑制对某类标识符的影响 |

- 抑制匹配**必须**同时接受主标识与替代标识；抑制**必须**参与"该检查是否运行"（文件级）与"条目是否产出"（元素级）两处判定，不得只在渲染时隐藏。
- **冗余抑制**：抑制未命中任何问题时视为冗余，可产出提示并提供"移除该抑制"的修复；冗余判定本身**不得**产生新的冗余提示（自反终止）。
- 抑制**必须不**改变文件语义：注释形式抑制若无法保证不影响编译产物，则该形式不得提供。

### 4.7 快速修复契约

```
applyFix(problemRef, fixRef):
  1. 复核问题仍存在（元素有效、区间仍落在同一元素内、版本相符）且修复可用性判定通过（必须廉价，不得触发全项目解析）
  2. 在单个写命令中执行：取得写意图 → 修改 → 提交
  3. 成功后立即对本文件标脏（不等去抖），使问题消失；失败则整体回滚至命令前快照
```

| 契约项 | 要求 |
|---|---|
| 可用性判定 | 产生问题时即绑定，应用前**必须**再判一次；判定失败 → 拒绝并提示"上下文已变化" |
| 描述 | 名称面向用户且动作明确；族名用于统计与批量归并；二者都必须提供 |
| 批量修复 | 同族修复可对多问题一次性应用；批量入口接收"问题集合 + 元素集合 + 完成回调" |
| 冲突 | 同批内两修复触碰同一区间 → **必须**串行执行且每条执行前重新定位；定位失败 → 跳过并计数 |
| 幂等与回滚 | 修复后重跑**必须**不再产出同一条目（否则视为修复缺陷，可作测试断言）；批量任一步出错 → 整批回滚（或按显式声明的逐条提交策略，默认为整批） |
| 抑制修复 | 独立一族：修改注释/注解以抑制问题；必须与"移除冗余抑制"互为逆操作 |

### 4.8 意图动作

```
IntentionDescriptor {
  id: string; family: string
  text: string                           // 面向用户名称，可含目标符号名
  categories: string[]                   // 菜单分类（声明式）
  requiresWriteAction: bool; previewMode: diff | fallback | none
  availabilityCost: cheap | expensive    // 声明成本，决定何时判定
}
```

- **上下文判定**：可用性判定输入**必须**限于（项目、编辑器、文件、偏移、可见区间、注入片段、选中元素），不得读取项目全局状态做启发式判定。
- **名称与成本上限**：允许为计算名称（如"重命名为 X"）做**局部**解析，但不得为此实例化全部意图——先按声明式元数据过滤，再逐条判定。一次光标位置的意图收集**必须**有总预算；超预算的意图直接视为不可用（丢弃而非错判）并计数；单次收集预算为毫秒级 `[推断]`。
- **预览**：**必须**在文件副本上执行并产出差异；副本不可安全执行（如需跨文件写入）时**必须**退化为"提示性差异"，**不得**为预览修改原文档。
- **过滤链**：收集后**必须**经过过滤扩展链（按语言、按后端角色、按检查关联）；过滤只能收窄，不能新增。
- **与检查的区别**：触发（自动 vs 显式）、产出（问题+修复 vs 变换本身）、持久显示（是 vs 否）、可批量（是 vs 一般否）、配置面（启用位/严重度/选项 vs 无）、失败表现（该检查本轮失效 vs 该意图不出现）。

### 4.9 注解器与外部注解器

**遍历式注解器**：平台对结构树逐元素调用，注解器对元素产出零到多条标注；标注经会话分配区间与严重度。会话携带**最低严重度阈值**，低于阈值的标注在产出侧即丢弃（用于"只保语法级反馈"的降级模式与"只显示错误"的视图级别）。注解器**必须**幂等、**必须不**修改文档、**必须**响应取消；单个注解器抛错只丢失它自己的标注。

**外部注解器（进程外工具结果注入）**：

```
Phase 1 collect:  输入 = (文件, 可见编辑器?, 是否已有错误)  输出 = 初始信息（可空）
Phase 2 annotate: 输入 = 初始信息                          输出 = 标注结果（可空）
Phase 3 apply:    输入 = (文件, 标注结果)                  输出 = 高亮条目（应用前复核版本）
```

| 契约项 | 要求 |
|---|---|
| 阶段 1 环境 | 读锁下、可见编辑器存在时可访问编辑器；"文件已有错误"时**可以**跳过（避免在不可编译状态跑工具） |
| 配对启用态 | 注解器可声明"配对的批量检查标识"；该检查未启用 → 整个注解器跳过，保证编辑器内与离线报告一致 |
| 版本绑定 | 阶段 1 结束时**必须**记录文档版本；阶段 3 前**必须**复核，不符 → 丢弃 |
| 变更取消 | 阶段 2 期间监听文档变更，变更即取消（工具应观察到取消并尽快退出） |
| 超时与隔离 | 每次运行**必须**有超时，超时视为取消；抛错 → 记录（附文件路径）并保留上一轮结果，**不得**使整个文件分析失败；上限由外部进程通道统一控制 `[推断]` |
| 索引未就绪 / 与检查关系 | 未就绪视为"无结果"而非错误，就绪后必须重试；产出**必须**能作为问题记录来源，但不得与之配对检查产出重复条目（重复高亮须标记） |

### 4.10 问题视图

```
ProblemsCollector {
  totalCount: int; files: FileId[]
  problemsOf(file): ProblemRecord[]; countOf(file): int; otherCount: int; otherProblems: ProblemRecord[]
}
```

- **集合模型**：按文件分桶 + 一个"其他"桶；两桶并集即全集，计数必须自洽（`total = Σ files + other`）。
- **去重**：以 `ProblemRecord.key` 去重（提供者 + 文件 + 行 + 列 + 文本摘要）；同键保留最早者并累加引用计数。同一区间被多个来源产出时**必须**保留并标记 `isDuplicateHighlight`，**不得**静默丢弃其中一条。
- **分组**：一级按提供者，二级按文件，三级按 `group`（检查分组路径）；"其他"桶一级按提供者。
- **跳转**：问题携带（文件、行、列）**和**偏移；优先用偏移，偏移失效则按行/列重新定位；定位失败则标为失效并保持可见（不得静默消失）。
- **导出与更新**：格式由转换器扩展提供，记录**必须**含文件路径、行、列、严重度、检查标识、描述，且**必须**可在无界面角色下执行；集合随"文件分析完成"事件增量更新，单个文件完成**不得**导致整个集合重建。

### 4.11 增量正确性与成本控制

任何高亮条目、问题记录、快速修复绑定关系**必须**携带四元组 `(fileId, generation, documentVersion, passId)`。应用或查询时三步复核：**代际**（与当前不等 → 丢弃）、**版本**（与文档当前不等 → 丢弃）、**区间**（必须满足 `start <= end <= 文档长度` 且落在产出时所属元素的当前范围内 → 否则丢弃）。

**禁止修补**：不允许"按偏移差量平移"挽救过期结果——被分析文本已改变时，任何平移都是猜测。丢弃**必须**计数并可见（见 §9），因为异常高的丢弃率本身就是"分析追不上输入"的信号。

| 成本手段 | 规则 |
|---|---|
| 单文件时间预算 | 每文件每轮有总预算；超预算的遍产出部分结果并记录，剩余在下一轮补齐 |
| 可视优先 | `priorityRange` 内计算**必须**先完成；`runForWholeFile` 检查例外但调度次序仍靠后 |
| 长任务让路 | 用户持续输入时，语义与检查遍**必须**被取消并以"文档已变更"为由重启；取消后不得立刻抢占其它文件 |
| 后台优先级与并发 | 可见文件 > 其它打开文件 > 预计算（仅源文件）> 缓存预热；同一（文件, 遍, 版本）最多一个在飞任务，并发由工作池与进度凭证共同限制，不得为单文件启动无上限线程 |
| 分级模式 | 存在"只保语法级反馈"模式：跳过语义与检查，仅保留语法元素标注，用于持续高速输入 |
| 用户可见状态 | 状态区**必须**显示"正在分析 + 当前遍名称 + 进度"；严重度汇总（交通灯）**必须**在整文件完成后才刷新，中途不得闪变 |

## 5. 不变量与约束

| 编号 | 不变量 |
|---|---|
| INV-1 | 任何分析结果必须携带（文件、代际、文档版本、遍 ID），不满足则不得应用。 |
| INV-2 | 版本或代际不符的结果必须整遍丢弃，禁止按条目修补。 |
| INV-3 | 应用阶段不得被取消打断；取消只发生在计算阶段。 |
| INV-4 | 一遍的结果只能替换"属于该遍且落在其 restrictRange 内"的标记。 |
| INV-5 | "已最新"只由应用成功后写入，且必须绑定文档版本。 |
| INV-6 | 检查启用判定必须是纯查询，不得实例化检查实现。 |
| INV-7 | 抑制必须在"是否运行"与"是否产出"两处生效，不得只在渲染期隐藏。 |
| INV-8 | 修复必须在单个写命令内完成；失败必须整体回滚。 |
| INV-9 | 修复后重跑不得再产出同一条目（幂等性可测）。 |
| INV-10 | 意图不得要求先存在问题；修复不得要求先建立问题视图记录。 |
| INV-11 | 外部注解器结果必须绑定收集时的文档版本，不符即丢弃。 |
| INV-12 | 单个检查/注解器/外部注解器的失败不得影响同文件其它产出。 |
| INV-13 | 问题集合总数必须等于各文件计数之和加"其他"计数。 |
| INV-14 | 编辑器不可见时允许跳过应用，但必须计入完成计数。 |
| INV-15 | 分析不得在输入线程上执行除词法着色之外的计算。 |

## 7. 故障模式与降级

| 故障 | 检测 | 用户可见 | 降级 | 恢复 |
|---|---|---|---|---|
| 检查实现 / 注解器抛错 | 运行期捕获 | 该项此次无产出，不弹窗 | D2：仅该项失效 | 下轮重试；连续多轮失败 → 禁用并提示 |
| 外部工具缺失/不兼容/超时/崩溃 | 配对检查启用但工具不可用；或超时/非零退出 | 提示"工具未配置"；否则保留上一轮结果 | D2：禁用配对注解器 | 用户配置或下次分析后自动恢复 |
| 索引失效（回哑模式） | 智能模式切换 | 顶部提示"索引中" | D1：跳过依赖索引的检查，保留语法级 | 索引就绪后全量重算 |
| 应用前版本变化 / 标记区间越界 | 版本复核与应用期校验 | 无（丢弃该条） | D0 | 自动（下轮重算） |
| 检查配置损坏 | 配置加载 | 提示并回退 | D2；严重时 D5：以默认配置启动 | 用户修复或重置 |
| 分析任务积压 | 队列长度/延迟指标 | 状态区显示"分析中"更久 | D1：延后非可见文件 | 输入停止后自行收敛 |
| 进程外通道不可用 | 连接探测 | 外部工具类问题消失 | D2 | 通道恢复后重试 |

**通用规则**：分析失败**不得**升级为文件不可编辑；**不得**自动关闭用户已启用的检查（只能禁用"反复失败的"并在通知中给出恢复入口）。

| 类别 | 内容 |
|---|---|
| 生命周期与耗时 | 分析开始、完成、取消（含原因）、重启（含原因）；每遍耗时、每阶段耗时、外部工具耗时、单文件总耗时 |

## 10. 扩展点

| 接缝 | 注册者必须遵守 |
|---|---|
| 检查声明 | 标识匹配 `[A-Za-z0-9_.-]+`；提供显示名与分组路径；声明默认启用与默认严重度、语言、是否哑感知、选项 schema；整文件运行必须显式声明 |
| 基础访问器 | 供检查在"未完全解析/受限"状态下使用的元素访问器；缺少语义信息时必须静默跳过而非抛错 |
| 注解器 | 语言绑定；必须幂等、不写文档、响应取消 |
| 外部注解器 | 三阶段契约；必须可取消、必须版本绑定；可声明配对检查以复用启用态 |
| 遍工厂 | 注册遍及其 ID 与前驱；ID 必须全局唯一；未声明前驱即视为可与任意遍并行，注册方必须自行声明依赖 |
| 高亮过滤器 / 错误过滤器 / 意图过滤器 | 高亮过滤器可丢弃条目且不得改严重度以外字段；错误过滤器可降级严重度但不得凭空创建条目；意图过滤器只可收窄意图集合 |
| 抑制器 / 隐式使用提供者 | 前者提供语言级抑制判定与"生成抑制动作"且必须可解释；后者声明元素被隐式使用，用于抑制"无用"类检查 |
| 问题转换器 / 问题面板提供者 | 前者负责导出格式且必须无界面可用；后者提供额外问题来源分区且必须遵守集合计数自洽 |

**隔离要求**：扩展元数据**必须**可静态校验（标识格式、必填项、语言存在性），校验失败不注册并记录；单个扩展抛错只影响其自身产出（INV-12），被禁用的扩展**必须**可查询禁用原因；**禁止**扩展在可用性判定或启用判定中执行重活（解析全项目、启动进程、访问网络），违反者按超时丢弃处理。
