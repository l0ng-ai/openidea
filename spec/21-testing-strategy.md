# 21 — 测试策略与接缝

> 范围：如何验证本类系统的行为；测试接缝的选择规则、夹具设计、各子系统的验证重点、缺陷回归策略。｜ 依赖：00、02–20。｜ 排除：具体测试框架、语言或工具。

## 1. 目的与范围

### 1.1 要解决的问题

这类系统有两个特性使测试变得困难：

1. **状态空间巨大**：文件系统、文档、语法树、索引、分析结果、界面状态互相依赖，任意组合都可能是缺陷来源。
2. **并发与增量**：多数行为发生在后台、可取消、可重启；"结果正确"不等同于"过程正确"。

因此测试策略的目标不是"覆盖每一行"，而是**在少数高位接缝上，用可复现的输入断言外部可观察的行为**，并让每条已发现缺陷沉淀为回归用例。

### 1.2 边界

不规定：测试运行器实现、断言库、覆盖率门槛数值、CI 流水线。只规定"测什么、在哪测、如何判定通过"。

## 2. 概念模型

### 2.1 四个测试层级

| 层级 | 输入 | 断言对象 | 典型耗时 | 占比目标 |
|---|---|---|---|---|
| 契约级 | 单个接口/扩展点的实现 | 契约要求（类型、幂等、异常、不变量） | 毫秒 | 高 |
| 子系统级 | 子系统 + 内存夹具 | 子系统对外状态与事件 | 十毫秒～秒 | 中 |
| 场景级 | 多子系统 + 真实但受控的载体 | 用户可见结果（问题列表、导航目标、重构后的文件） | 秒 | 中低 |
| 系统级 | 完整进程/前后端对 | 启动、协议、恢复、性能 | 分钟 | 低 |

**规则**：能用低层级证明的，不得上升层级；能用契约级证明的，不得写场景级。

### 2.2 接缝（Seam）

接缝 = **可以替换实现、且替换后仍能观察真实行为的最小边界**。

本系统只有五类接缝（按可覆盖面从高到低）：

| 编号 | 接缝 | 替换物 | 能覆盖 |
|---|---|---|---|
| S1 | 扩展点集合 | 注入伪造的扩展实现 | 任何"以扩展接入"的能力的装配、顺序、隔离 |
| S2 | 文档 ↔ 虚拟文件 ↔ 语法树 | 内存文件系统 + 内存文档 | 编辑、解析、索引、分析、重构的端到端数据流 |
| S3 | 动作 + 数据上下文 | 构造上下文、调用动作 | 全部用户可见命令的可用性与结果 |
| S4 | 运行配置 + 进程边界 | 假可执行文件（脚本化输出/退出） | 启动参数、环境、输出解析、生命周期 |
| S5 | 协议边界 | 录制/回放的消息流 | 前后端同步、语言服务、调试适配 |

**选择规则（必须遵守）：**

1. **优先最高位接缝**：能在 S1 证明装配正确，就不在 S3 重复。
2. **默认接缝是 S2**：语言无关能力的默认验证方式，是"给一组文件 + 一次编辑，断言树/索引/高亮/重构结果"。
3. **接缝数量最小化**：一个子系统至多引入一个新接缝；新接缝必须有书面理由（旧接缝无法表达该行为）。
4. **不得为测试而扩展生产接口**：如果需要"测试专用入口"，应把该入口设计为正式的诊断能力（见各文档 §9）。

### 2.3 夹具（Fixture）

| 夹具 | 语义 | 必须提供的保证 |
|---|---|---|
| 内存文件系统 | 支持目录/文件/只读/符号链接/大小写策略/事件 | 与真实文件系统的可观察语义一致；可注入外部变更 |
| 内存文档 | 支持修改、撤销、监听、快照 | 与真实文档的变更语义一致 |
| 假时钟 | 控制去抖、超时、缓存过期 | 可推进、可回退禁止 |
| 假执行器 | 按脚本产生 stdout/stderr 与退出码 | 可模拟挂起、被杀死、部分输出 |
| 录制协议 | 前后端/语言服务消息序列 | 可注入延迟、丢包、重连 |
| 诊断快照 | 索引快照、扩展注册快照、模型快照 | 可作为黄金文件比对 |

## 3. 数据模型

```
TestSeam {
  id: S1..S5
  replacedComponent: ComponentRef
  observableOutputs: OutputSpec[]     // 事件、模型状态、渲染结果、协议消息
  determinism: injected | recorded | real
}

TestCase {
  seam: TestSeam
  fixture: Fixture[]
  given: Input[]                      // 文件内容、编辑操作、协议消息、配置
  when: Operation                     // 一个动作/一次编辑/一次查询
  then: Assertion[]                   // 外部可观察断言
  invariants: InvariantRef[]          // 引用各文档 §5 的 INV 编号
}
```

## 4. 行为契约

### 4.1 单次测试的执行契约

```
prepare(fixture)
given(inputs)
when(operation)            // 必须显式等待到"静止点"
assert(observable)
teardown()                 // 必须释放全部后台任务与句柄
```

- **静止点**：所有异步工作必须被显式排空（队列为空 + 无运行中任务 + 无等待中的定时器），不得用睡眠等待。
- **无残留**：teardown 后断言"无存活后台任务、无未释放的容器、无未注销的监听器"。
- **无顺序依赖**：任一用例可单独运行、可任意顺序运行。
- **确定性**：同一输入重复运行结果必须一致；依赖时间的断言必须使用假时钟。

### 4.2 并发类行为的验证契约

必须验证以下四类断言，且都必须可重复：

1. **可取消性**：在任意检查点取消 → 不产生部分可见结果（或产生的结果被明确标记为不完整并被丢弃）。
2. **版本一致性**：结果携带输入版本；输入变更后旧结果被丢弃（不是"修补"）。
3. **串行化**：并发发起多个写操作 → 最终状态等于某个串行顺序的结果，且不出现半更新。
4. **无死锁**：在受控线程模型中并发运行 N 次（N 足够大以致可复现竞争），必须全部完成或全部可取消。

### 4.3 扩展契约测试

对每个扩展点，必须存在**一组共享断言**，对每个实现运行：

- 类型/属性约束满足；
- 可用性判定不抛异常（且在最坏输入下不耗时超过预算）；
- 失败时被隔离且不污染其他实现；
- 动态装卸后不残留引用；
- 顺序稳定（同一注册集合多次解析结果一致）。

### 4.4 缺陷回归规则

- 每个已确认缺陷 → 一个最小回归用例，**锚定在导致缺陷的最低接缝**。
- 回归用例必须包含"缺陷触发的原始输入"，不得只断言修复后的状态。
- 若缺陷源于并发时序，必须附带可复现的调度注入方式（假时钟/受控队列），不得依赖自然竞争。

## 5. 不变量与约束

| 编号 | 不变量 |
|---|---|
| TINV-1 | 任一用例可独立运行且结果与顺序无关。 |
| TINV-2 | 用例不得依赖真实网络、真实时钟、真实用户目录。 |
| TINV-3 | 所有异步结果必须可排空到静止点后断言。 |
| TINV-4 | 夹具行为必须与真实实现的可观察语义一致（差异必须在夹具文档中列明）。 |
| TINV-5 | 断言只针对外部可观察输出，不断言内部调用序列。 |
| TINV-6 | 每个缺陷必须有回归用例，且锚定最低可用接缝。 |
| TINV-7 | 测试不得改变生产代码的可见接口以求便利。 |

## 6. 对外能力契约（测试基础设施）

```
createFixture(kind, options) -> Fixture
awaitQuiescence(timeout) -> Status
injectExternalChange(fixture, change) -> void
assertNoLeaks(scope) -> Report
snapshot(kind) -> Artifact              // 索引/注册表/模型快照
replay(recording) -> MessageStream
```

要求：这些能力必须同时可用于**诊断**（生产环境导出最小状态），而不是仅测试可用。

## 7. 故障模式与降级

| 故障 | 表现 | 处理 |
|---|---|---|
| 用例不稳定（flaky） | 同一输入偶发失败 | 判定为缺陷而非噪声：定位依赖的隐藏时序或共享状态；禁止用重试掩盖 |
| 静止点永不到达 | 测试挂起 | 超时后导出线程转储与任务队列快照，作为失败证据 |
| 夹具与真实实现语义偏差 | 测试通过但线上失败 | 夹具必须与真实实现共享同一组契约测试 |
| 场景级用例过慢 | 反馈周期长 | 下沉到 S2；场景级只保留"跨子系统串联"的最小集 |
| 协议录制过期 | 回放失败 | 录制必须带版本；版本不符时明确失败而非静默放行 |

## 8. 资源与性能预算

| 层级 | 单例预算 | 说明 |
|---|---|---|
| 契约级 | < 50 ms | 不得创建容器 |
| 子系统级 | < 2 s | 允许创建最小容器与内存夹具 |
| 场景级 | < 30 s | 允许启动真实进程（假可执行文件） |
| 系统级 | 分钟级 | 仅在合并前/夜间运行 |

测试套件必须支持"按接缝选择运行"（S1/S2 快，S5 慢），以便日常反馈与提交前验证分离。

## 9. 可观测性

失败诊断包必须包含（与各文档 §9 的诊断能力对齐）：

1. 输入快照（文件树内容、文档内容、协议输入）。
2. 事件轨迹（有序事件及其时间戳/序号）。
3. 后台任务清单（运行中、排队中、已取消）。
4. 锁与线程状态（若超时）。
5. 扩展注册快照与代际号。

## 10. 扩展点

第三方扩展作者必须能在**不启动完整 IDE** 的前提下验证自己的扩展：

- 提供最小容器 + 只注册被测扩展；
- 提供 S1 夹具（注入扩展、断言解析顺序与隔离）；
- 提供 S3 夹具（构造数据上下文、调用动作、断言结果与撤销单元）。

## 11. 对照实现（证据锚点）

| 结论 | 证据 |
|---|---|
| 测试被平台作为一等能力（测试发现/执行/结果模型） | 模块 `intellij.platform.testIntegration*`；插件 `intellij.testRunner.plugin`、`JUnit`、`TestNG-J` |
| 覆盖率作为独立子系统 | 模块 `intellij.platform.coverage`、`intellij.platform.coverage.agent`；插件 `Coverage` |
| 性能验证工具已内置 | 插件 `com.jetbrains.performancePlugin`（Performance Testing） |
| 语言无关的"结构搜索"可作为断言手段 | 插件 `intellij.structuralsearch.plugin`；模块 `intellij.platform.duplicates*` |
| 远端/协议边界真实存在，需要回放式测试 | 模块 `intellij.platform.rpc*`、`intellij.platform.kernel*`、`intellij.platform.split.protocol` |
| 诊断能力（冻结分析、线程转储解析）已内置 | 模块 `intellij.platform.diagnostic.freezeAnalyzer`、`intellij.platform.threadDumpParser` |
